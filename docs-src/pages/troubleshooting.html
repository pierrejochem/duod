Troubleshooting

Start with duod get <app> and duod history <app>. The message and the event log usually name the cause. Add -log-format json to duod run for structured logs.

Traefik Docker provider fails with "400 Bad Request"

Cause: Docker Engine 29 rejects Docker API versions below 1.40, and older Traefik clients use them. Fix: upgrade Traefik to v3.6 or newer.

Rollout fails with a missing network message

Cause: a routed service is not attached to duod-edge. Fix: add duod-edge to the service's networks and declare it as external: true. See Write a service.

The preview never becomes healthy

  • Check that healthCheck.path returns expectStatus when called through Traefik, not only inside the container.
  • Check that routes[].port is the container port and routes[].replicas equals deploy.replicas.
  • With revisionHeader, the app must return the ${BG_REVISION} commit in that header.
  • Raise progressDeadline for slow images or start-up.
  • Confirm traefik.probeURL is reachable from duod, and that the duod entrypoint exists in Traefik's static config.

"Traefik did not load the new file" or confirm timeout

duod waits confirmTimeout for Traefik to serve the new generation, then restores the old file. Check that Traefik's file provider watches traefik.dynamicDir, that the directory is mounted in the Traefik container and that the provider uses watch: true.

The app is Degraded and does not retry

A failed revision is remembered in failedRevision. Push a fix as a new commit, or run duod retry <app>.

A rollout stays Paused

With autoPromotionEnabled: false duod waits. Run duod promote <app>, set autoPromotionSeconds or enable auto promotion.

A rollout is queued

The RolloutQueued event means maxConcurrentRollouts is reached. It starts when another rollout ends.

Apache: configtest fails

duod restores the previous include file and does not reload. Run apachectl configtest yourself to see the error, and check your proxy.template.

Git fetch errors

duod get <app> shows Git error. Check that the user running duod can read the repository (SSH key or token), and that source.revision and source.path exist.

Webhook returns 401 or 403

The secret or signature header does not match. Use the same secret in the Git server and in webhookSecret (global) or source.webhookSecret (per app), and the endpoint that matches your Git server's header. See Webhooks.

Still stuck?

Open an issue on GitHub with the output of duod get <app>, duod history <app> and the duod logs.
