duod vs Argo CD and Argo Rollouts

duod copies the vocabulary and the guarantees of Argo CD and Argo Rollouts blueGreen, but runs on one Docker host. If you know Argo, the table below tells you what to use in duod.

What is different

  • No cluster. One operator controls one Docker host. For several hosts, run one duod per host.
  • Blue/green only. There is no canary strategy yet. Traefik weighted services could add it later.
  • Health through the proxy. The analysis uses Traefik's private entrypoint, so it tests the real network path.
  • Plain Compose files. There are no new resource types. Your compose file is the deployment manifest.

When to choose duod

Choose duod when your services run on a VM or bare-metal Docker host and you want GitOps, zero-downtime releases and one-command rollbacks without Kubernetes. Choose Argo CD and Argo Rollouts when you already run Kubernetes.

Limitations

  • One Docker host per operator instance.
  • Traffic switching is all at once (blue/green).
  • A path-scoped revision only reacts to changes inside source.path.
  • Images are pulled during the rollout (pull: always). Build them in CI and reference them by tag or digest in Git.
  • Requires Traefik v3 (the Header() rule syntax and the noop@internal service). Use v3.6 or newer with Docker Engine 29+.
