Configuration reference: duod.yaml

duod reads one YAML file, by default /etc/duod/duod.yaml. Run duod validate -config <file> to check it. Values like ${DUOD_TOKEN} are replaced from the environment where noted.

Minimal example

apiToken: ${DUOD_TOKEN}
apps:
  - name: shop
    source:
      repoURL: git@github.com:acme/deploy.git
      path: apps/shop
    healthCheck: {path: /health}
    proxy:
      routes:
        - name: web
          port: 3000
          rule: Host(`shop.example.com`)
          tls: {certResolver: le}

A full example with three apps is in examples/duod.yaml. YAML anchors (&health, <<: *source) keep repeated settings short.

apps[].proxy (Traefik)

proxy.type is traefik or apache. It defaults to traefik when routes are set and to apache otherwise. All routes of an app switch in one atomic file write.

namerequiredRoute id, lowercase letters, digits and -, up to 31 characters.

portrequiredContainer port.
replicas1Compose replicas (1 to 50). Must equal the service's deploy.replicas.

Several routes in one app

Use this only for services that must switch together, such as a frontend and the BFF it was built against:

- name: portal
  source: {repoURL: git@github.com:acme/deploy.git, path: apps/portal}
  proxy:
    routes:
      - {name: ui,  port: 80,   rule: "Host(`portal.example.com`)"}
      - {name: bff, port: 8080, rule: "Host(`portal.example.com`) && PathPrefix(`/bff`)", healthPath: /bff/health}

App names and validation

An app name must match ^[a-z0-9][a-z0-9-]{0,40}$ and be unique. duod validate reports every problem at once. For Apache apps see Apache instead of Traefik.
