Webhooks and Git

duod polls Git every pollInterval (default one minute). A push webhook makes rollouts start within seconds.

Endpoints

EndpointRefreshesVerified with
POST /api/v1/webhookall appswebhookSecret
POST /api/v1/apps/<app>/webhookone appsource.webhookSecret

Only apps whose source.path changed roll out. One webhook on a monorepo is enough.

Supported Git servers

ServerHeader duod checks
GitHubX-Hub-Signature-256 (HMAC-SHA256)
Gitea, ForgejoX-Gitea-Signature
GitLabX-Gitlab-Token

Use the same secret as webhookSecret when you create the webhook in your Git server. The webhook only triggers a fetch, so duod never trusts the payload.

Set up a GitHub webhook

  1. Open your GitOps repository, then Settings, Webhooks, Add webhook.
  2. Payload URL: https://admin.example.com/duod-hook/api/v1/webhook (see below).
  3. Content type: application/json. Secret: the value of DUOD_WEBHOOK_SECRET.
  4. Event: Just the push event.

Expose the endpoint through Traefik

duod listens on loopback by default. Publish only the webhook path, for example with a router for PathPrefix(`/duod-hook`) on your admin host, a stripPrefix middleware, and a service pointing at http://<host>:9800. Set listen so that Traefik can reach it, and keep apiToken set.

Do not expose the whole API to the internet. Mutating calls need the Bearer token, but only the webhook path has to be public.

Monorepo behavior

An app's target revision is the newest commit that touched its own source.path. A commit to apps/api does not redeploy apps/shop, even though both track main. Files shared between services and located outside their folders do not trigger a rollout.

Force a sync

duod sync shop
