Apache instead of Traefik

duod can switch traffic with Apache on the host. Use it when Apache already terminates TLS and you do not want to add Traefik.

How it works

  • Each slot publishes the app on its own loopback port, 127.0.0.1:${BG_PORT}.
  • duod rewrites an include file that it owns (proxy.configFile).
  • duod runs apachectl configtest. If it fails, the old file is restored.
  • duod then runs apachectl graceful.

Apache apps are serialized on the configtest and reload step, because Apache validates its whole configuration at once. Their deploys and analyses still run in parallel.

Configuration

apache:
  configTest: ["apachectl", "configtest"]
  reload: ["apachectl", "graceful"]

apps:
  - name: shop
    source: {repoURL: git@github.com:acme/deploy.git, path: apps/shop}
    slots:
      blue:  {port: 18081}
      green: {port: 18082}
    healthCheck: {path: /health}
    proxy:
      type: apache
      configFile: /etc/apache2/duod/shop.conf

Ports must be unique across all apps and colors. Include the file from your vhost with Include.

Default template

If you do not set proxy.template, duod routes all traffic to the active slot and exposes the preview under /_preview/ for smoke tests:

ProxyPreserveHost On
ProxyPass        /_preview/ http://127.0.0.1:{{.PreviewOrActivePort}}/
ProxyPassReverse /_preview/ http://127.0.0.1:{{.PreviewOrActivePort}}/
ProxyPass        / http://127.0.0.1:{{.ActivePort}}/
ProxyPassReverse / http://127.0.0.1:{{.ActivePort}}/
